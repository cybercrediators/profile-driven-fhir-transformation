# Overview over metrics and experiments

## Metrics on project level

- can be executed by the `run_eval.py` script in the `eval` folder
- writes report to: `eval/reports/<project>.json`
- certain metrics (M0c, M3, M6) require `--regenerate` (generate transformation artifacts again)

| Name  | What it measures                                                              | Concretely                                                                                                                                                                                                                            | Implemented in                                                       |
|-------|-------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------|
| `M0a` | `$validate`: is the resource conform to the profile                           | output resource is sent to Matchbox, then `$validate` against its `meta.profile` (fallback: base type) (e.g. `Patient` missing a required `identifier` fails                                                                          | e.g. `eval/e16_run.py`                                               |
| `M0c` | Reproducibility of regeneration of the project (same maps for repeated runs)  | Maps paired by target SD url, then compared by content. `id` changes still counts as identical. Reports `rule_identical`, `identical/maps_compared`, and `drifted` list naming each url with its F1 score                             | `eval/run_eval.py::_reproducibility` + `eval/canonicalize.py`        |
| `M1`  | Data preservation of every mapped source value contained in the output        | For example: a correspondence `geburtsdatum` to `Patient.birthDate` with source value `1982-02-20`, that value must appear at `Patient.birthDate` in some output `Patient` (not positional)                                           | `eval/metrics.py::data_preservation`                                 |
| `M2`  | Behavior of two maps producing the same FHIR output (same input)              | Both compared maps are run on the identical source data. The outputs must be equal after normalization (not positional)                                                                                                               | `eval/metrics.py::behavioral_equivalence` + `eval/normalize_fhir.py` |
| `M3`  | Rule-level precision, recall, F1-score of regenerated maps against the golden | Each rule is reduced to a set of fields (target path, source element consumed, transform, parameters) with neutral variable names. Then `TP = generated ∩ correct`, `missing = correct − generated`, `spurious = generated − correct` | `eval/run_eval.py::_candidate_vs_golden` + `eval/canonicalize.py`    |
| `M5`  | Remaining (placeholders) to measure the work which is left for edits          | Counts rules containing a placeholder (e.g. `TODO-SOURCE-FOR-*`, `TODO-MAP-*_SOURCE`, `TODO-resolveConceptMap`, `TODO_EXTENSION_URL` where a binding cannot be derived from the profile alone. A minimal-mode (`-msm`) map reports 0  | `eval/metrics.py::remaining_todo`                                    |
| `M6`  | Edit distance from the (correct) map                                          | Both maps are serialized to JSON and compared line-wise. Reports `1 similarity`. Beware: still formatting-sensitive after canonicalization. Report as effort.                                                                         | `eval/metrics.py::edit_distance`                                     |
| `M7`  | Features of FHIR constructs a profile declares compared what the map contains | Per construct (slicing, extension, choice type,...) reports `present_in_profile` count and `emitted_in_map` (true/false)                                                                                                              | `eval/metrics.py::feature_matrix`                                    |
| `M8`  | Extraction completeness                                                       | Percentage of the profile snapshot elements appearing in the mappable-field registry                                                                                                                                                  | `eval/metrics.py::extraction_completeness`                           |
| `M8b` | Extraction content check                                                      | Confirms the features that are (actually) represented in the registry                                                                                                                                                                 | `eval/e8b_gap_extraction.py`                                         |
| `M9`  | Graceful degradation (no missing fields unreported)                           | Counts profile elements that are neither extracted nor placeholdered (`dropped_element_count`).                                                                                                                                       | `eval/metrics.py::graceful_degradation`                              |

## Experiments

| ID    | What it does                                                                                                        | Implemented in                                              |
|-------|---------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------|
| `E10` | Marfoglia/MOTU compared with the published maps: fetch, profiles, transforms (counts), then queries (Q1-Q5)         | `eval/e10_marfoglia/`                                       |
| `E11` | HAPI's own `generateMapFromMappings` on the same inputs                                                             | `eval/e11_hapi_baseline/`                                   |
| `E13` | LLM map-generation baseline using 3 models. Frozen outputs, then scored                                             | `eval/e13_llm/` (`build_prompts.py`, `score.py`)            |
| `E14` | Synthetic profiles of increasing feature complexity, single and bundle mode                                         | `eval/e14_synthetic.py`                                     |
| `E15` | hand-built kfdm self-comparison assessed by output equivalence                                                      | `eval/e15_kfdm_compare.py`                                  |
| `E16` | (unseen) project evaluation: generation, upload, transform, wired-bundle `$validate`, offline metrics               | `eval/e16_run.py` (protocol: `docs/e16_preregistration.md`) |
| `E18` | Comparative evaluation of the integrated production arms (`table`, `deterministic-automap`, `llm-automap`, `agent`) | `eval/e18_agent_modes.py`, `eval/e18_aggregate.py`          |
